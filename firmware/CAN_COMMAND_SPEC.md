# STM32(HAL) CAN コマンド仕様書

対象: STM32 側ファーム実装チーム。本ドキュメントは**仕様のみ**であり、STM32ファーム自体（`torobo2026_hal`）のコードはこのリポジトリの担当範囲外。

経路: スマホ(HMI) → rosbridge → ROS2 `/robot/command` → `cmd_vel_to_joy`(`/joy`) → `pscon_node`(`pscon_data`) → `can_node` → SPI → クラシックCAN 500kbps → **STM32(HAL)**

## 1. CAN payload のビット対応表

ハンドは吸着式のため仰角機構は無い。アームは上下左右の平面2軸ジョグのみ。

### can_send_data[1]（CANフレームの2バイト目、0-indexed）: 機構コマンド

| bit | 動作 | 起動方式 | 内容 |
|---|---|---|---|
| bit0 | 射出シーケンス | 立ち上がりエッジ | エアシリンダ、1発 |
| bit1 | 回収シーケンス | 立ち上がりエッジ | アームを所定角回転→戻す |
| bit2 | 設置シーケンス・関所 | 立ち上がりエッジ | 所定高さで離す |
| bit3 | 設置シーケンス・城門 | 立ち上がりエッジ | 設置と同一機構、高さプリセットのみ関所と相違 |
| bit4 | アーム手動ジョグ ↑ | **ホールド**（1の間だけ動作、0で停止） | アームを上方向に動かす |
| bit5 | アーム手動ジョグ ↓ | **ホールド** | アームを下方向に動かす |
| bit6 | アーム手動ジョグ ← | **ホールド** | アームを左方向に動かす |
| bit7 | アーム手動ジョグ → | **ホールド** | アームを右方向に動かす |

### can_send_data[2]（CANフレームの3バイト目）: 旋回方向・吸着

| bit(バイト内) | 動作 | 起動方式 | 内容 |
|---|---|---|---|
| bit0 | 旋回方向（左） | 状態値（1の間旋回中） | 走行スティックの旋回操作由来（`cross_bt==-1`）。機構制御ではなく走行系の参考情報 |
| bit1 | 旋回方向（右） | 状態値 | 同上（`cross_bt==1`） |
| bit2 | **吸着ON/OFF** | **トグル状態値**（ONの間1を保持し、OFFで0） | ハンドの吸着機構。スマホ画面ボタン、またはパッドのRTを押すたびにON/OFFが切り替わる |

## 2. 起動条件・シーケンス方式

- **bit0-3（定型シーケンス）は立ち上がりエッジで起動**（0→1になった瞬間の1回だけトリガー）。
- **bit0-3にホールド動作は無い**。ビットが1のまま保持されても再起動・連続動作はしない（次にトリガーするには一度0に戻ってから再度1にする必要がある）。
- **bit4-7（アーム手動ジョグ）はホールド方式**。ビットが1の間だけ対応方向へ動かし続け、0に戻ったら即座に停止する（エッジトリガーではない）。定型シーケンス実行中に手動ジョグが立った場合の優先順位（シーケンス継続 or 中断）はSTM32側の状態機械の実装判断とする。
- **吸着（can_send_data[2] bit2）は状態値**。スマホ/パッド側でトグル操作の結果としてON/OFFの状態そのものを毎フレーム送っており、STM32側は「このビットが1ならポンプ/バルブON、0ならOFF」という単純な状態追従でよい（エッジ検出は不要）。
- シーケンス自体（射出/回収/設置の一連動作）はSTM32上のローカル状態機械が閉ループで実行する。ROS2/Piはトリガー（bit0-3）・動作方向（bit4-7）・状態（吸着bit2）を送るのみで、シーケンス完了までの制御ループには入らない。

## 3. 安全則

- **E-stop相当受信で全機構即時停止**。実行中のシーケンスがあれば安全な状態で中断し、**吸着は必ずOFFにする**（保持物を落とすリスクより、E-stop中に意図せず物を掴み続ける方が危険という判断）。
- **射出は誤発火防止のため立ち上がりエッジのみで発火する**（bit0が1で来ても、既に1だった場合は再発火しない。ノイズ等でチャタリングしても多重発射しない設計とすること）。
- **アーム手動ジョグ(bit4-7)・吸着(bit2)は通信断で確実に止まる/OFFになること**。上流でデッドマン切れ・estop・接続断が起きると`/joy`のbuttons全体が0に落ちる設計だが、CAN受信側でも一定時間ビット更新が無ければ安全側（機構停止・吸着OFF）に倒すこと（フェイルセーフの二重化）。
- 上流（`pscon_node`）側は `/joy` のデッドマン（最終コマンドから200ms超で全ボタン0）と `estop`/`release` ラッチで安全ゲートを持つ。CAN受信側もこれに依存せず、通信断・データ異常時は安全側（機構停止・吸着OFF）に倒すこと。

## 4. pscon_data → CAN payload の対応

`pscon_node`（`torobo2026_ros2_rp`）は `/joy` の `buttons[0..8]` を1ビットずつ詰めて `pscon_data`（`std_msgs/msg/UInt32`）として publish する。`buttons[8]`（吸着トグル状態）は既存のcross_bt（旋回方向、`axes[6]`由来）が占有していたbit8/9と衝突しないよう、同じ上位バイト内の空きビットである**bit10**に割り当てる。

```
/joy.buttons[i]  (i=0..7: 1=押下エッジ中/0=無し, i=8: 吸着ONの間1)
        │  (bt_list[i] & 0x01) << i         （bit0-7のみ。bit8はbit10へ個別に載せる）
        ▼
pscon_data (uint32, LSB→MSB)
┌─────────────┬─────────────┬───────────────────┬─────────────┐
│   byte3     │   byte2     │       byte1        │   byte0     │
│ st_rx_data  │ st_ry_data  │ cross_bt + 吸着(*)  │  buttons    │
│ (bits24-31) │ (bits16-23) │ (bits8-15)         │ (bits0-7)   │
└─────────────┴─────────────┴───────────────────┴─────────────┘
     │               │              │                   │
     ▼               ▼              ▼                   ▼
can_send_data[4] can_send_data[3] can_send_data[2]  can_send_data[1]
                                   ┌──────────────────┐  ┌────┬────┬────┬────┬────┬────┬────┬────┐
                                   │bit7..3(未使用)│bit2│bit1│bit0│  │bit7│bit6│bit5│bit4│bit3│bit2│bit1│bit0│
                                   │        │吸着│右旋回│左旋回│  │アーム→│アーム←│アーム↓│アーム↑│城門│関所│回収│射出│
                                   │        │(ﾄｸﾞﾙ)│(状態)│(状態)│  │(ホールド)         │(立ち上がりエッジ)         │
                                   └──────────────────┘  └────┴────┴────┴────┴────┴────┴────┴────┘
```
(*) 吸着は `pscon_data` の bit10 = `can_send_data[2]` の bit2（bit8=can_send_data[2]のbit0起算）。

- `pscon_data` の bit0-7（byte0/`can_send_data[1]`）＝`/joy.buttons[0..7]`。bit0-3=`launch`/`intake`/`checkpoint`/`gate`（`cmd_vel_to_joy.py`の`COMMAND_BUTTON_MAP`定数、エッジパルス）、bit4-7=アーム上下左右の手動ジョグ（`cmd_vel_to_joy.py`の`BUTTON_ARM_UP`等の定数、ホールド値）。
- `pscon_data` の bit8/9（`can_send_data[2]`のbit0/1）＝旋回方向（`cross_bt`、走行スティック由来）。**機構コマンドではないので本書の対象外**（走行制御は別経路）。
- `pscon_data` の bit10（`can_send_data[2]`のbit2）＝吸着トグルの現在状態（`/joy.buttons[8]`、`cmd_vel_to_joy.py`の`BUTTON_SUCTION`定数）。
- `can_node`（チーム側実装）は `pscon_data` の各バイトをそのまま `can_send_data[1..4]` に載せる想定。
- `/joy.buttons[0..3]` は `cmd_vel_to_joy` 側で受信後 約150ms(3フレーム) だけ1になるエッジパルスなので、CAN側で見ても bit0-3 は短パルスの立ち上がりとして観測される。STM32側はこの立ち上がりでシーケンスを起動する（本書 2節）。
- `/joy.buttons[4..7]` はホールド中(操作している間)ずっと1で、離すと即座に0に戻る。STM32側はこのビットが1の間だけ機構を動かし、0で停止する。
- `/joy.buttons[8]`（吸着）はトグルのON状態である間ずっと1で、OFFにすると即座に0に戻る。STM32側はこのビットの値にそのまま追従する（1でON、0でOFF）。
