# STM32(HAL) CAN コマンド仕様書

対象: STM32 側ファーム実装チーム。本ドキュメントは**仕様のみ**であり、STM32ファーム自体（`torobo2026_hal`）のコードはこのリポジトリの担当範囲外。

経路: スマホ(HMI) → rosbridge → ROS2 `/robot/command` → `cmd_vel_to_joy`(`/joy`) → `pscon_node`(`pscon_data`) → `can_node` → SPI → クラシックCAN 500kbps → **STM32(HAL)**

## 1. CAN payload byte1 のビット対応表

`can_send_data[1]`（CANフレームの2バイト目、0-indexed）の各ビットが機構の起動トリガーになる。

| bit | 動作 | 起動方式 | 内容 |
|---|---|---|---|
| bit0 | 射出シーケンス | 立ち上がりエッジ | エアシリンダ、1発 |
| bit1 | 回収シーケンス | 立ち上がりエッジ | アームを所定角回転→戻す |
| bit2 | 設置シーケンス・関所 | 立ち上がりエッジ | 所定高さで離す |
| bit3 | 設置シーケンス・城門 | 立ち上がりエッジ | 設置と同一機構、高さプリセットのみ関所と相違 |
| bit4 | アーム手動ジョグ + | **ホールド**（1の間だけ動作、0で停止） | 回収アームを手動で正方向に動かす |
| bit5 | アーム手動ジョグ − | **ホールド** | 回収アームを手動で逆方向に動かす |
| bit6 | 仰角手動ジョグ + | **ホールド** | 射出/設置の仰角・高さを手動で正方向に動かす |
| bit7 | 仰角手動ジョグ − | **ホールド** | 射出/設置の仰角・高さを手動で逆方向に動かす |

## 2. 起動条件・シーケンス方式

- **bit0-3（定型シーケンス）は立ち上がりエッジで起動**（0→1になった瞬間の1回だけトリガー）。
- **bit0-3にホールド動作は無い**。ビットが1のまま保持されても再起動・連続動作はしない（次にトリガーするには一度0に戻ってから再度1にする必要がある）。
- **bit4-7（手動ジョグ）はホールド方式**。ビットが1の間だけ対応機構を動かし続け、0に戻ったら即座に停止する（エッジトリガーではない）。定型シーケンス実行中に手動ジョグが立った場合の優先順位（シーケンス継続 or 中断）はSTM32側の状態機械の実装判断とする。
- シーケンス自体（射出/回収/設置の一連動作）はSTM32上のローカル状態機械が閉ループで実行する。ROS2/Piはトリガー（bit0-3）または動作方向（bit4-7）を送るのみで、シーケンス完了までの制御ループには入らない。

## 3. 安全則

- **E-stop相当受信で全機構即時停止**。実行中のシーケンスがあれば安全な状態で中断する。
- **射出は誤発火防止のため立ち上がりエッジのみで発火する**（bit0が1で来ても、既に1だった場合は再発火しない。ノイズ等でチャタリングしても多重発射しない設計とすること）。
- **手動ジョグ(bit4-7)は通信断で確実に止まること**。上流でデッドマン切れ・estop・接続断が起きると`/joy`のbuttons全体が0に落ちる設計だが、CAN受信側でも一定時間ビット更新が無ければ安全側（機構停止）に倒すこと（フェイルセーフの二重化）。
- 上流（`pscon_node`）側は `/joy` のデッドマン（最終コマンドから200ms超で全ボタン0）と `estop`/`release` ラッチで安全ゲートを持つ。CAN受信側もこれに依存せず、通信断・データ異常時は安全側（機構停止）に倒すこと。

## 4. pscon_data → CAN payload の対応

`pscon_node`（`torobo2026_ros2_rp`）は `/joy` の `buttons[0..7]` を1ビットずつ詰めて `pscon_data`（`std_msgs/msg/UInt32`）として publish する。

```
/joy.buttons[i]  (i=0..7, 1=押下エッジ中/0=無し)
        │  (bt_list[i] & 0x01) << i
        ▼
pscon_data (uint32, LSB→MSB)
┌─────────────┬─────────────┬─────────────┬─────────────┐
│   byte3     │   byte2     │   byte1     │   byte0     │
│ st_rx_data  │ st_ry_data  │ cross_bt    │  buttons    │
│ (bits24-31) │ (bits16-23) │ (bits8-15)  │ (bits0-7)   │
└─────────────┴─────────────┴─────────────┴─────────────┘
                                              │
                                              │ 下位8bit(byte0)をそのまま
                                              ▼
                                    can_send_data[1] (CANペイロード2バイト目)
                                    ┌────┬────┬────┬────┬────┬────┬────┬────┐
                                    │bit7│bit6│bit5│bit4│bit3│bit2│bit1│bit0│
                                    │仰角−│仰角+│アーム−│アーム+│城門│関所│回収│射出│
                                    │(ホールド)         │(立ち上がりエッジ)         │
                                    └────┴────┴────┴────┴────┴────┴────┴────┘
```

- `pscon_data` の bit0-7（byte0）＝`/joy.buttons[0..7]`。bit0-3=`launch`/`intake`/`checkpoint`/`gate`（`cmd_vel_to_joy.py`の`COMMAND_BUTTON_MAP`定数、エッジパルス）、bit4-7=アーム/仰角の手動ジョグ（`cmd_vel_to_joy.py`の`BUTTON_ARM_UP`等の定数、ホールド値）。
- `can_node`（チーム側実装）はこの下位8bitをそのまま `can_send_data[1]` としてCANフレームに載せる想定。
- `/joy.buttons[0..3]` は `cmd_vel_to_joy` 側で受信後 約150ms(3フレーム) だけ1になるエッジパルスなので、CAN側で見ても bit0-3 は短パルスの立ち上がりとして観測される。STM32側はこの立ち上がりでシーケンスを起動する（本書 2節）。
- `/joy.buttons[4..7]` はホールド中(スマホ画面のボタンを押している間)ずっと1で、離すと即座に0に戻る。STM32側はこのビットが1の間だけ機構を動かし、0で停止する。
